# Busybar status

[English version](README.md)

Статус на [BUSY Bar](https://busy.app) (светодиодная лента 72×16 с колесом): что играет, что делают нейросети, сколько вы работали, ближайшая встреча и живы ли серверы. Колесо переключает экраны, кнопка **OK** листает страницы экрана, а большая центральная кнопка **Start / Pause** делает ещё одно дело на трёх экранах (см. ниже).

Две части: JavaScript-приложение, которое работает **на баре**, и агент, который работает **на компьютере** (Node 24) и снабжает его данными. На Mac к агенту прилагаются значок в строке меню и страница настроек в браузере.

| Экран | Что показывает | OK / Start |
|---|---|---|
| Музыка | обложка 16×16 со скруглёнными углами, название и исполнитель (длинные прокручиваются), линия прогресса, которую бар двигает сам, по желанию значок play / пауза | Start: по желанию пуск и пауза |
| Агенты | токены и стоимость по ценам API текущего 5-часового окна Claude, время до сброса, токены за день (`D`) и неделю (`W`), линия «сколько окна прошло» и маскот (свой у Claude или радужное привидение): работает, как только любой агент начал работу, танцует, когда нейросеть закончила, моргает и спит. Запущено несколько агентов (Claude, Codex, Gemini, Aider, …)? | OK: следующий агент, затем маскот |
| Время работы | по умолчанию квадраты активности за пять недель, как на GitHub (строка — неделя, у сегодняшней клетки белый верх), с итогами недели и месяца; или вчера и сегодня («Сегодня» зелёным, пока вы работаете, жёлтым на паузе) | OK: следующий вид (квадраты, вчера и сегодня, с какого времени и сколько подряд) |
| Календарь | три вида: **выкл** (только ближайшая встреча с отсчётом), **3 недели** (по неделе в строке, с понедельника, крупные квадраты, дни со встречами красные, сегодня в белой рамке) и **месяц** (пять недель мелких квадратов, как на экране «Время работы»); рядом с сеткой дата и ближайшая встреча. Какой вид первый — настройка; за N минут до встречи всплывает поверх любого экрана | OK: следующий вид. Start: следующая встреча |
| Серверы | скруглённая плашка со значком на каждый сервер (зелёная — в сети, серая — не отвечает); чем серверов больше, тем плашки меньше: значок уступает место первой букве, а потом одному цвету. Или список, или таблица из двух колонок (влезает больше серверов; длинное название бежит строкой) | OK: вид (иконки, список, таблица). Start: на иконках — карточка одного сервера за раз (значок, название и адрес, состояние и сколько оно длится; адрес и время полупрозрачные); в списке и таблице строки поднимаются на одну за четыре быстрых шага |

**Кнопки работают по одному правилу:** колесо меняет **экран**, **OK** — **состояние** экрана (вид, следующий агент, маскот), а **Start / Play / Pause** — **дополнительная функция** экрана (музыка: пуск / пауза, серверы: карточка каждого на иконках, строки вверх в списке и таблице, календарь: следующая встреча).

У каждого экрана свой акцентный цвет, его можно сменить. Напоминания: встреча скоро, вы отработали N часов, пора на перерыв, сервер упал, нейросеть закончила.

## Быстрый старт (macOS)

Нужны macOS 13+, Node 24 (`nvm use` берёт версию из `.nvmrc`), инструменты командной строки Xcode (`xcode-select --install`, для `swiftc`), [`media-control`](https://github.com/ungive/media-control) для экрана музыки (`brew install media-control`) и BUSY Bar в той же сети Wi-Fi.

```sh
git clone git@github.com:solowey1/busybar-status.git && cd busybar-status
nvm use && npm ci
npm run build                                   # приложения для бара -> apps/*/dist/*.tgz
npm run app:install -- --addr <ip бара> --password <пароль бара>   # приложение со всеми экранами
npm run app:run     -- --addr <ip бара> --password <пароль бара>
(cd mac-agent && ./tray/install.sh)             # собирает и запускает приложение в строке меню и агента
```

Дальше: значок в строке меню → **Настроить…** (страница `http://127.0.0.1:8787/ui`). На вкладке **Общее** введите адрес бара и пароль, нажмите **Привязать** (в приложение на баре запишутся IP Mac и порт) и **Сохранить**. macOS один раз спросит, можно ли читать календарь.

Готовые пакеты для macOS, Windows и Linux лежат в каждом [релизе](https://github.com/solowey1/busybar-status/releases) (см. [Пакеты](#пакеты)). Убрать приложение из строки меню: `mac-agent/tray/install.sh uninstall`.

## Настройки

**На баре** (Настройки → приложение): язык (Русский / English), IP Mac и порт, а также переключатель для каждого из пяти экранов (Музыка, Агенты, Серверы, Календарь, Время работы). Больше ничего: страница настроек самого бара плоская и маленькая, подписи на ней только английские (прошивка берёт один текст на подпись и не умеет следовать языку приложения; страница настроек на Mac переведена полностью). Токена на баре нет: агент узнаёт бар по адресу (тому, что задан на вкладке «Общее») и разрешает ему только читать состояние и нажимать большую кнопку; всё остальное требует токен, а он нужен лишь браузеру и хукам.

**В браузере** (`/ui`, из значка в строке меню): всё остальное, по вкладке на экран. Изменения сохраняются на Mac и доходят до бара за несколько секунд.

| Вкладка | Настройки |
|---|---|
| Общее | адрес и пароль бара, **Привязать**; **язык всего приложения** (бар, эта страница, меню в строке меню, уведомления; применяется сразу; при первом запуске берётся язык системы, русский или иначе английский); **порядок экранов** (по нему идут колесо и вкладки); запуск при входе; показывать приложение в Доке / строке меню / в обоих местах / нигде; имя `.local` для этой страницы (но не `busybar`: так называется сам бар); вид значка в строке меню |
| Музыка | обложка и её непрозрачность; значок play / пауза (зелёный, на паузе жёлтый); большая кнопка **Start / Pause** пускает и ставит на паузу; акцентный цвет (на паузе полупрозрачный) |
| Агенты | **страница с маскотом** (последняя после агентов по кнопке OK; отдельного экрана для неё на колесе нет); **агент по умолчанию**; маскот: Claude, привидение или без маскота (привидение достаётся и другим нейросетям, когда они сообщают о конце работы); **перекрывать другие экраны при завершении** (по умолчанию выключено: тогда сообщают только звук и светодиод, а новость ждёт на экране AI); акцентный цвет |
| Время работы | с какого вида начинать (тепловая карта или вчера и сегодня); напоминание через N часов; перерыв каждые N минут; сколько дней хранить (30); сколько простоя считать паузой; акцентный цвет; квадраты активности |
| Календарь | **сетка** (выкл, 3 недели, месяц: с какого вида начинать); за сколько минут показывать встречу; какие календари не учитывать; акцентный цвет (по умолчанию красный) |
| Серверы | список (название, адрес, значок, цвета; порядок меняют стрелки); с какого вида начинать (иконки, список, таблица); цвета «в сети» / «не отвечает» |
| Приложение | автолистание, прятать пустые экраны, сколько держать название экрана после поворота колеса (700 мс, 0 — не показывать), звук уведомлений |

Страница настроек удобна и на телефоне (тот же адрес в той же сети, ссылка с токеном есть на вкладке «Общее»): вкладки превращаются в полосу сверху, строки встают в столбик.

Если выбрать показ **нигде**, настройки останутся доступны по адресу в браузере (`http://127.0.0.1:8787/ui`, а при заданном имени ещё и `http://<имя>.local/ui`: пока имя задано, страница слушает и порт 80, так что `:8787` не нужен). Браузер, который страницы ещё не видел, один раз спросит токен (на вкладке «Общее» есть готовая ссылка с ним). Имя публикует в локальной сети macOS (Bonjour); `busybar` не принимается, потому что `busybar.local` — это сам бар.

## Приложение в строке меню (macOS)

Щелчок по значку (радужное привидение; другие варианты на странице настроек) открывает меню: состояние агента и порт, адрес бара, доступ к календарю, **Настроить…**, **Перезапустить** и **Отключить** (останавливает и агента). Агент запускается как дочерний процесс приложения и поднимается снова, если упал. Запуск при входе — переключатель на странице настроек, его выполняет macOS как элемент входа (Системные настройки → Основные → Объекты входа); пока вы не включили, ничего не устанавливается.

Календарь читает само приложение, поэтому разрешение принадлежит ему, а не терминалу, из которого что-то запущено. После пересборки приложения macOS может спросить снова.

## Уведомления от нейросетей

Хук сообщает бару, что нейросеть закончила. Для Claude Code добавьте в `~/.claude/settings.json`:

```json
{
  "hooks": {
    "Stop": [{ "hooks": [{ "type": "command", "command": "node /ПУТЬ/mac-agent/bin/notify.mjs claude_done" }] }],
    "Notification": [{ "hooks": [{ "type": "command", "command": "node /ПУТЬ/mac-agent/bin/notify.mjs claude_wait" }] }]
  }
}
```

Бар узнаёт, что агент работает, примерно за секунду и без хуков: агент на Mac следит за процессами агентов (нагрузка процесса и того, что он запустил), их журналами сессий и хуками. Хук делает это точным: добавьте `UserPromptSubmit` → `node /ПУТЬ/mac-agent/bin/notify.mjs claude_start` для начала (без всплывающего окна), а хук `Stop` выше сразу ставит конец. Несколько агентов сразу (Claude, Codex, Gemini, Aider, OpenCode, Cursor, Goose) перечислены на странице настроек; **OK** на экране AI переключает их, а в настройках выбирается, какой показывать первым. Токены и стоимость есть только у Claude, у остальных видно состояние. Любой другой инструмент (Codex, Gemini, скрипт) может вызвать `node mac-agent/bin/notify.mjs ai_done "Codex: проект"` и `ai_wait`. Токены и стоимость берутся из логов Claude Code в `~/.claude/projects`. Стоимость — это сколько те же токены стоили бы по ценам API (`PRICES` в `mac-agent/src/sources/claude.mjs`), а не расход по вашей подписке.

## Время работы

Агент каждые 15 секунд смотрит, сколько прошло без клавиатуры и мыши, и складывает активное время по дням в `~/.local/state/busybar-status/work.json` (последние N дней, по умолчанию 30). Считает он только пока работает и Mac не спит, так что для целых дней включите запуск при входе.

## Приложения на баре: все экраны сразу или только нужные

Репозиторий — монорепа: из одного кода собираются несколько приложений для бара.

| Приложение | id | Что это |
|---|---|---|
| **Busybar status** | `app.solowey.busybar-status` | все экраны в одном: колесо ходит по ним в заданном порядке, а встреча, упавший сервер или конец работы нейросети всплывают поверх любого экрана |
| Status: Music | `app.solowey.status-music` | только экран музыки |
| Status: Agents | `app.solowey.status-agents` | только экран агентов (расход, агенты, страница с маскотом) |
| Status: Servers | `app.solowey.status-servers` | только экран серверов |
| Status: Calendar | `app.solowey.status-calendar` | только экран календаря |
| Status: Work time | `app.solowey.status-work` | только экран времени работы |

Ставьте приложение со всеми экранами или любые отдельные (`npm run app:install -w apps/music -- --addr <ip бара> --password <пароль>`, либо `.tgz` из релиза через `busy-cli app install`). Бар запускает одно приложение за раз, поэтому отдельные экраны открываются из меню приложений бара, колеса между ними нет, и каждый показывает только новости своего экрана; зато он маленький (только свой код) и просит у агента только свои данные. Страница настроек на Mac знает, какие экраны есть на баре: вкладка экрана, которого там нет, показывает, как его установить, вместо настроек. Общие настройки (язык, IP и порт Mac) при сохранении записываются во все наши приложения на баре, а в новое — один раз, когда оно появится.

Замер на баре (прошивка 1.3.1): приложение со всеми экранами прошло все экраны и состояния с кучей 128 КиБ, а с 96 КиБ не запустилось; в манифестах 192 КиБ (все экраны) и 128 КиБ (отдельный экран), остальная память остаётся прошивке. Затем нагрузочный тест на этих размерах: сводное приложение приняло 592 случайных нажатия за 4 минуты (агент тем временем то работал, то простаивал, в таблице семь серверов), а каждое приложение на один экран — 100 секунд такого же, без ошибок и перезагрузок; 256 КиБ не нужно. Большая куча не бесплатна: она берётся из памяти, которую прошивка держит для своих служб (в том числе для веб-сервера, который отвечает странице настроек и агенту), а бару, которому её не хватает, отвечает медленно или перезагружается. «Loading», который бар на миг показывает, к памяти не относится: прошивка показывает его, когда у приложения на дисплее ничего нет, а приложение раньше стирало старый экран перед тем, как нарисовать новый (и раз в минуту стирало всё); теперь уходящие элементы заменяются пустыми в том же запросе, что рисует новые, и замер дисплея (3300 кадров за 140 секунд с нажатиями) не нашёл ни одного кадра «Loading» против 40 раньше.

## Пакеты

В каждом релизе есть архивы `busybar-status-<версия>-<система>` для `darwin-arm64`, `darwin-x64`, `linux-x64`, `linux-arm64` и `win-x64`. В каждом свой Node и, в папке `apps`, `.tgz` каждого приложения для бара.

| Система | Что внутри | Чего нет |
|---|---|---|
| macOS | `Busybar status.app` со значком в строке меню (подпись ad-hoc, без нотаризации: в первый раз откройте правым щелчком → Открыть) | – |
| Windows, Linux | агент и `start.cmd` / `start.sh`, которые запускают его и открывают страницу настроек | приложения в строке меню, музыки и календаря; время работы на Linux требует `xprintidle` или GNOME |

Пакеты собирает GitHub Actions (`.github/workflows/release.yml`), а не вручную: тег с версией запускает сборку на раннере каждой системы и прикладывает пакеты к релизу. Попробовать сборку без тега можно с вкладки Actions («Run workflow»): пакеты придут артефактами запуска. Пакеты для Windows и Linux автор на этих системах не запускал. (Workflow запускает `node mac-agent/tools/package.mjs <система>`; пакеты для macOS собираются на Mac.)

## Как это устроено

```
компьютер: агент (Node 24) <--- HTTP раз в 3 с, крошечный ответ, если ничего не изменилось ---> бар: JS-приложение
  media-control, логи Claude Code, простой ввода, EventKit (через приложение в строке меню), ping серверов
```

Приложение на баре не принимает входящих соединений и на прошивке 1.3.1 не может писать в хранилище, поэтому оно само обращается к агенту. Агент хранит номер ревизии и держит каждый запрос до двух секунд, пока ничего не изменилось (долгий опрос), так что новость доходит до бара в тот же момент. Прогресс трека, время работы и отсчёты бар считает сам; бегущую строку и `countdown` рисует прошивка. На дисплей уходят только изменившиеся элементы. Настройки экранов приходят в том же ответе.

`~/.config/busybar-status/config.json` (закрыт для остальных, правится со страницы настроек): порт, токен (для браузера и хуков), адрес и пароль бара, серверы, игнорируемые календари, значок и выбор Дока, имя `.local`, переключатель запуска при входе и `settings` экранов (см. `mac-agent/src/appsettings.mjs`).

## Разработка

```sh
npm run typecheck             # все приложения для бара
npm run build                 # все приложения -> apps/*/dist/*.tgz
npm run versions              # у всех приложений версия из package.json
npm test                      # агент: 30 тестов
node mac-agent/tools/icons.mjs appmeta apps/status/src/appmeta   # перерисовать иконки-привидения для бара (скопировать в остальные приложения)
```

`packages/core/src/` — код приложений для бара (TypeScript, строгий режим, работает в JerryScript прошивки, не в Node: движок, экраны, тексты), а `apps/<имя>/` — по одному приложению: `main.ts` с перечнем экранов, `appmeta/` (манифест, настройки, иконки) и, для экрана агентов, анимация-пульс. Куча 192 КиБ (все экраны) и 128 КиБ (один экран); буферы экран держит, только пока он на дисплее, а нехватка кучи останавливает приложение и может перезагрузить весь бар (при замере так и было ниже 112 КиБ), так что держите выделение памяти на кадр небольшим. `mac-agent/` — агент: `src/` исходники, `ui/` страница настроек, `tray/` приложение в строке меню (Swift), `tools/` иконки и упаковка. Волна на странице маскота — нативная анимация бара, `apps/{status,agents}/src/animations/pulse.anim`; её пишет `node mac-agent/tools/anim.mjs pulse` (формат `.anim`, «bicycle1», описан в [`anim_file_format.h` прошивки](https://github.com/busy-app/busybar-firmware/blob/dev/lib/anim_file/anim_file_format.h); писатель кладёт сырые кадры BGRA8888, их бар играет; BGR888 не сыграл). Прошивка сама крутит её по кругу, поэтому приложение отправляет элемент один раз. Значки плашек серверов — светодиодные 9×9 версии иконок [Lucide](https://lucide.dev) (лицензия ISC), их делает `mac-agent/tools/glyphs/raster.py` в `packages/core/src/glyphs.json` (одна строка из 81 символа на значок); кнопки на странице настроек тоже используют иконки Lucide. Перед правкой приложения для бара прочитайте `AGENTS.md`.

Справка по шаблону BUSY (сборка, манифест, ресурсы) — в [английском README](README.md#busy-app-template-reference).
